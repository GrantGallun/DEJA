# Game-agnostic event detection and automatic HUD discovery

Research performed 2026-10-24. Scope: event perception and HUD discovery; other researchers cover replay players and capture/overlay backends. Source was read, not executed. Repository metadata records the inspected state, not a promise that the software works today.

## What do the closest actual implementations do, and how much game-specific work do they require?

### Takeaway
The strongest inspected systems already implement screenshot-to-event pipelines, reusable visual/OCR profiles, and temporal event suppression. They mostly require game-specific regions, exemplars, text rules, assets, or training. Sightline is particularly close to the practical “teach an example, run a cheap detector, trigger a clip” fallback; OverTrack shows how much specialist work comprehensive game-state extraction entails.

### Cited Findings

- **Sightline, SessionGoblin/sightline-computer-vision:** Windows app/runtime with region visual detection, OCR, OBS capture/actions, and clipping workflows. Read README, `perception_core/detectors.py`, `image_detection.py`, `sightline_runtime/gate.py`, and region-preview editor code. Profiles supply regions/detectors; `score_keywords` does normalized substring matching; match modes include contains, equals, nonempty, regex. This is reusable machinery, not an automatically learned semantic game model. [README](https://github.com/SessionGoblin/sightline-computer-vision/blob/main/README.md), [detectors](https://github.com/SessionGoblin/sightline-computer-vision/blob/main/perception_core/detectors.py).
- Sightline's image detector loads an exemplar from file/base64, resizes it to the crop, applies configured preprocessing, computes mean image difference, and combines this with foreground similarity. Its foreground heuristic estimates a template's dominant grayscale background and foreground overlap. This is especially relevant to a one-example UI detector but does not automatically discover an event's meaning. [Actual image-scoring implementation](https://github.com/SessionGoblin/sightline-computer-vision/blob/main/perception_core/image_detection.py#L26).
- Sightline also implements frame hashes, per-screen detection cooldowns, repeated-event cooldowns/backoff, and preview controls for template similarity. These are practical precedents for avoiding one clip per positive frame and for letting users inspect/tune a detector. [Gate](https://github.com/SessionGoblin/sightline-computer-vision/blob/main/sightline_runtime/gate.py), [preview editor](https://github.com/SessionGoblin/sightline-computer-vision/blob/main/sightline_runtime/customer_app/region_preview_modal.py).
- **Sightline status/license:** author site says archived and no longer actively developed. GitHub API reports `archived:false`, last push `2026-09-11`, and `license:null`; the recursively inspected tree contained no LICENSE file. Use “public source, author describes project as discontinued”; do not call it permissively licensed. [Author's current project description](https://quacksoftware.com/sightline/), [metadata](https://api.github.com/repos/SessionGoblin/sightline-computer-vision).
- **OverTrack CV, overtrack-gg/overtrack-cv:** read Apex combat processor and substantial Valorant killfeed processor, plus tree/README/license. Apex `CombatProcessor` loads a `16_9.zip` region definition, named PNG text templates for assists/eliminations/knockdowns, applies unsharp masking, then OpenCV normalized template correlation. Its event labels come from the developer's template dictionary. [Combat source, inspected revision](https://github.com/overtrack-gg/overtrack-cv/blob/bf45a5393fb4b894ff35b4ee197afbb6852b72d8/overtrack_cv/games/apex/processors/combat/combat_processor.py).
- OverTrack Valorant killfeed processing has friendly/enemy kill templates, agent icons, weapon templates, wallbang/headshot templates, explicit screen-relative crop geometry, contour heuristics, and Tesseract name reading. It is strong precedent for pixel-only structured event inference, but emphatically game-specific. Source even includes interactive matplotlib debug plotting in agent parsing; this inspected public revision should not be presumed production-ready. [Valorant killfeed implementation](https://github.com/overtrack-gg/overtrack-cv/blob/bf45a5393fb4b894ff35b4ee197afbb6852b72d8/overtrack_cv/games/valorant/processors/killfeed/killfeed_processor.py).
- OverTrack has separate Apex, Overwatch, and Valorant processor trees. API reports last push `2022-08-06`, `archived:false`. LICENSE explicitly says GNU Affero GPL and discretionary commercial exceptions; bundled AGPL text is present. [Tree](https://api.github.com/repos/overtrack-gg/overtrack-cv/git/trees/master?recursive=1), [LICENSE](https://github.com/overtrack-gg/overtrack-cv/blob/master/LICENSE), [metadata](https://api.github.com/repos/overtrack-gg/overtrack-cv).
- **GameVideoEdit, Friend-Xu/GameVideoEdit:** read `keywords.py`, `roi_templates.py`, substantial detector and coarse-to-fine scanner source. The system targets PUBG/Peace Elite, with per-platform/language presets and user ROI annotation. Regions are normalized and reusable between videos. Keyword configuration generates regex rules; fuzzy strategy independently scores constituent signal words with RapidFuzz `partial_ratio`, subject to prefixes/descriptor/anti-signal rules. This reduces OCR brittleness while retaining per-game text semantics. [Keyword engine](https://github.com/Friend-Xu/GameVideoEdit/blob/master/app/core/keywords.py), [ROI templates](https://github.com/Friend-Xu/GameVideoEdit/blob/master/app/core/roi_templates.py), [README](https://github.com/Friend-Xu/GameVideoEdit/blob/master/README.md).
- GameVideoEdit uses sparse text-presence scanning to find candidate time windows, dense scanning inside those windows, and selective OCR; detector source includes counter tracking, event stacking, and a sliding multi-frame OCR fusion buffer. This is a useful implementation reference for gating expensive perception and stabilizing event evidence; the ROIs still arrive as inputs. [Coarse-to-fine scanner](https://github.com/Friend-Xu/GameVideoEdit/blob/master/app/core/coarse_to_fine.py), [detector/fusion](https://github.com/Friend-Xu/GameVideoEdit/blob/master/app/core/detector.py). GPL-3.0 metadata; last push `2026-07-19`, not archived. [Metadata](https://api.github.com/repos/Friend-Xu/GameVideoEdit), [LICENSE](https://github.com/Friend-Xu/GameVideoEdit/blob/master/LICENSE).
- **rfypych/video-highlight-detection:** read OCR, visual, audio detectors and configuration. OCR crops configured chat coordinates, preprocesses for Tesseract, checks Minecraft death-message phrases and optional player name, and deduplicates messages with a set. Visual detection estimates Minecraft hearts using red HSV thresholds and configured health region; audio detects frequency-band peaks, onset strength, RMS jumps. These are heuristics, not demonstrated game-agnostic kills/clutches. [OCR implementation](https://github.com/rfypych/video-highlight-detection/blob/main/detectors/ocr_detector.py), [visual implementation](https://github.com/rfypych/video-highlight-detection/blob/main/detectors/visual_detector.py), [audio implementation](https://github.com/rfypych/video-highlight-detection/blob/main/detectors/audio_detector.py), [configuration](https://github.com/rfypych/video-highlight-detection/blob/main/config.yaml).

### Inferences

- “Game-agnostic engine with per-game profiles” is established in this sample. It shifts integration from executable code into authored data but does not eliminate maintenance. SmartReplay's strongest potential distinction is reducing profile creation/repair through automatic proposals and user examples, not merely storing normalized ROIs/templates. This follows from Sightline's configurable detectors and OverTrack's asset-heavy processors above.
- Sightline is an architectural reference, with unresolved reuse permission; OverTrack is an algorithm reference with copyleft/commercial-license considerations. Neither needs to be adopted wholesale to learn from its mechanics.

### Gaps

- None of these repositories was run, and README demos/performance claims were not reproduced. No inspected benchmark establishes low gameplay overhead, robustness across UI updates, or fully automatic unseen-game event semantics.
- No general train-one-example gameplay detector with verified cross-game evaluation was found in this bounded search. Sightline verifies that exemplar-based authoring exists, not that a single image reliably captures every visual variant.

## How much mechanism-level prior art exists for automatic HUD discovery and semantic event detection?

### Takeaway
Temporal stability as a way to discover overlaid graphics is old; unsupervised localization followed by automatic per-stream detector training also exists outside games. The exact SmartReplay combination of intermittent histogram prominence, recurrence/run statistics, spatial agreement, and coactivation grouping was not found in the inspected sources. That is a limited search result, not evidence of research novelty or a patent conclusion.

### Cited Findings

- **2005 opaque-logo patent:** US20050078222A1, published April 14, 2005, describes selecting scene-change frames, accumulating per-pixel temporal stochastic statistics, comparing variability to noise, producing a logo mask, and refining it using neighboring pixels. It concerns opaque stable television logos rather than recurring gameplay event banners. It is direct mechanism-level precedent for separating overlays from changing world imagery through temporal pixel statistics plus spatial cleanup; it does not establish equivalence to this prototype's histogram prominence, intermittent run criteria, or coactivation clustering. This is a technical observation only; no legal status/scope opinion is offered. [Primary patent text](https://patents.google.com/patent/US20050078222A1/en).
- **2021 Automatic TV Logo Identification for Advertisement Detection without Prior Data:** explicitly proposes unsupervised logo localization, automatic gathering/labeling of positive and negative examples, then training a detector per input stream. Locator uses graph-based segmentation, empirically fixed corner/size filters, and temporal heatmap heating/annealing; it treats persistence around 30 seconds as evidence. This overlaps “discover stable screen region, obtain examples, produce detector,” although channel logos and advertisement absence differ from short recurring game events. No code release was verified; the primary paper was available in search's full extraction, while a subsequent open was rate-limited. [Primary article](https://www.mdpi.com/2076-3417/11/16/7494).
- **2020 Visual Analysis of Computer Game Output Video Stream for Gameplay Metrics:** Bioshock 2 study averages 30 frames to blur moving scene content, trains HUD/weapon cascade classifiers from manually prepared positive/negative examples, then analyzes localized health/energy colors and text. Its related work describes static-logo masks for HUD presence. This establishes gameplay-video HUD analysis and using scene motion versus UI stability; its classifiers are game-specific and supervised, not the prototype's unsupervised recurring-element clustering. Do not transfer its reported accuracy to SmartReplay. [Primary open-access paper, Method and Algorithm A](https://pmc.ncbi.nlm.nih.gov/articles/PMC7302570/).
- **2025 Gameplay Highlights Generation:** fine-tunes X-CLIP on labeled events from five FPS titles. It uses one-second clips, per-game prompts, and an 80/20 dataset split; reported 94.3% classification accuracy is not a held-out-game universal detection guarantee. The paper reports a 13-FPS gameplay drop in its tested setup, so this is no basis for assuming negligible overhead. Its in-house gameplay fine-tuning code/data were not located; it links Microsoft's generic X-CLIP. [Primary paper](https://arxiv.org/html/2505.07721v1).
- **Actual X-CLIP implementation inspected:** `encode_video` runs visual encoding plus multi-frame integration; `cache_text` caches encoded prompts; `forward` normalizes video/text features and calculates prompt similarity logits with `einsum`. This is reusable video/text embedding machinery, not released game-event weights or guaranteed instruction-following gameplay reasoning. Microsoft's VideoX repository API reports archived, last push `2024-06-03`; license metadata says NOASSERTION/Other, so this review makes no license claim. [X-CLIP model source](https://github.com/microsoft/VideoX/blob/master/X-CLIP/models/xclip.py), [metadata](https://api.github.com/repos/microsoft/VideoX).
- **Local comparison:** `discovery.py` uses 32-bin per-pixel intensity histograms, subtracts a smoothed histogram background, selects prominent bins, applies spatial consensus to at-mode activations, then thresholds recurrence, duration, occupancy and variability. `grouping.py` clusters temporal coactivation; `variants.py` hashes cropped appearances; `profile.py` emits unlabeled detector ROIs/templates. These are region/event candidate proposals; no module read here maps arbitrary semantic user requests to verified events. [Local discovery](C:/Code/HACKTX/smartreplay/discovery.py), [grouping](C:/Code/HACKTX/smartreplay/grouping.py), [variants](C:/Code/HACKTX/smartreplay/variants.py), [profile](C:/Code/HACKTX/smartreplay/profile.py).
- The local `lookup.py` already contains a second route: semantic image-search queries, aspect/size filtering, image deduplication, edge-structure clustering, across-image low-variance consensus, then edge matching into user footage. Source explicitly treats web images as geometry/label aids and calls for re-deriving templates in the user's footage. This is present code, not a validated semantic-search result. [Local lookup](C:/Code/HACKTX/smartreplay/lookup.py).

### Inferences

- Established: frame/crop matching, OCR rules, temporal event gating, normalized profiles, temporal stability for overlaid graphics, and automatically bootstrapping stream-specific detectors. Research-adjacent uncertainty: discovering useful *intermittent* HUD events reliably under arbitrary game rendering/UI, assigning semantics without annotations, and maintaining confidence after UI/layout changes.
- The product could be distinctive even where components are established. A dependable workflow spanning discovery, one-example correction, event indexing, semantic requests, and immediate replay requires engineering and validation; discovering repeated opaque pixels alone does not solve it.
- The current assumptions are strongest for repeated, opaque, screen-anchored, seconds-long banners. Alpha blending, animated elements, changing numbers/names, moving HUD, rare events, and the scene's own recurrent/stationary regions can violate them. These are hypotheses derived from the code, not measured failure rates.

### Gaps

- Search did not prove no equivalent algorithm exists. Relevant neighboring areas include broadcast logo detection, subtitle localization, motion segmentation/background models, frequent-pattern mining, and few-shot temporal action localization.
- No verified released code for an end-to-end unsupervised cross-game HUD-to-semantics system was found. No causal ablation currently establishes that prototype grouping identifies an element's semantics rather than correlated UI effects.

## What should SmartReplay build and measure next?

### Takeaway
Keep automatic discovery as a proposal generator and test it aggressively; pair it with a concrete “show me one example” correction path. Separate the event detector from natural-language request interpretation so semantic flexibility does not force expensive full-frame video understanding into every frame.

### Cited Findings

- The local profile already has ROIs, exemplar templates, observed timing, and null labels; this is a natural boundary for a reviewed event definition. [Profile implementation](C:/Code/HACKTX/smartreplay/profile.py).
- Existing implementations show complementary pieces: exemplar preview/scoring and cooldowns in Sightline, multi-frame OCR fusion/counter tracking and coarse-to-fine gating in GameVideoEdit, and game-specific contextual extraction in OverTrack. [Sightline](https://github.com/SessionGoblin/sightline-computer-vision/blob/main/perception_core/image_detection.py), [GameVideoEdit](https://github.com/Friend-Xu/GameVideoEdit/blob/master/app/core/coarse_to_fine.py), [OverTrack](https://github.com/overtrack-gg/overtrack-cv/blob/master/overtrack_cv/games/apex/processors/combat/combat_processor.py).

### Inferences

- **Recommended minimal workflow:** after a short representative session, propose regions/event clusters with a few matched and unmatched thumbnails. Let the user name an event, accept/reject a proposal, or mark one exemplar and crop. Build a masked/edge template from the confirmed example; collect additional positives and hard negatives as the user corrects it. One example initializes a hypothesis; it does not justify a reliability promise.
- **Event verification:** score inside an ROI with cheap template/edge matching and/or OCR; require multiple-frame evidence, hysteresis, minimum duration, and a rearm condition (absence or an event-ID/counter change). Keep confidence/provenance and distinguish “seen,” “verified,” “unknown.” Cooldowns alone can merge real close-together events; a monotonically increasing kill counter can be better where available. These are design recommendations informed by the source above.
- **Semantic path:** map “show my last death” into a named event query over timestamped detector output. For a new event type, ask for an example or use a slower vision/language pass on candidate snippets to suggest a label/verify evidence. A general model can propose; a confirmed detector can handle repeated runtime observations. Benchmark the actual scheduling/resource costs before choosing model frequency or claiming real-time overhead.
- **Discovery benchmark (proposed, not existing results):** separate train/calibration footage from held-out sessions and titles; annotate visible event intervals and UI boxes, including explicit no-event footage. Freeze thresholds before evaluation. Compare temporal variance/background model, fixed ROI template/OCR baseline, user exemplar baseline, current histogram/run/spatial method, and full method with coactivation grouping. Ablate histogram prominence, spatial consensus, recurrence, and grouping separately.
- **Measure proposal quality separately from replay usefulness:** UI mask precision/recall or IoU; event precision/recall with specified onset tolerance; false saves per hour; missed-event rate; duplicate/merged-event rate; discovery time and required event repetitions; number of user corrections; transfer across resolution/aspect/UI scale/language; detector recalibration after updates. Count unknown/rejected outcomes rather than silently dropping them.
- **Stress cases:** rare one-off events; event text lasting less than the 2-fps sampling interval; opaque versus translucent UI; moving/animated HUD; scrolling killfeed with repeated names; dark/static scenery; pause/menu/cutscene/loading; subtitles, webcam and streamer overlays; 16:9 versus ultrawide and HUD scaling; non-FPS games; event-free videos. For performance, measure game frametime distribution, CPU/GPU/VRAM/RAM, capture/encoding/inference costs, and export latency on the target Windows hardware.
- **Go/no-go criterion should be empirical:** if discovery proposals do not lower setup burden or improve held-out event recall at a tolerable false-save rate relative to teaching a crop, keep them optional. A useful product may succeed with minimal user teaching even if fully unsupervised cross-game semantics does not.

### Gaps

- Dataset size, sampling cadence, operating thresholds, and acceptable false-save rates need product targets and measured tradeoffs; this review invents no numeric success benchmark.
- The audit's synthetic-positive/Doom-negative coverage is insufficient to choose among these alternatives. No new execution or production edits were performed for this review.
