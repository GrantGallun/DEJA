# Complete replay and recording applications: source-read prior art

## Which existing applications most closely overlap SmartReplay?

### Takeaway
GameHQ is the closest source-inspected complete Windows application: continuous recording, hotkey/controller save, and playback inside an in-game overlay already exist together. WKI-Clipper is the most attractive permissively licensed recorder reference; RePlays is a more established libobs-based application reference. All three inspected playback paths use completed saved files, rather than a demonstrated low-latency direct rolling-buffer-to-PiP path. Sources: [GameHQ recorder](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/src/capture/SegmentRecorder.cpp#L587), [GameHQ viewer](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/src/ui/qml/components/OverlayViewer.qml#L152), [WKI save](https://github.com/WKImods/WKI-Clipper/blob/1b6aff3e9700b5868d252a3f1108b39c5ae773d9/WKI_Clipper/Services/ReplayBufferService.cs#L1245), [RePlays save](https://github.com/lulzsun/RePlays/blob/db1abe5682ab37c731b1f2fd18412d40dd4eb2f6/Classes/Recorders/LibObsRecorder.cs#L614).

#### 1. UnderFusion/GameHQ — nearest complete-app base

- **Identity/platform/architecture:** C++20, Qt 6.8.3/QML, Windows Graphics Capture (WGC), Media Foundation, WASAPI, SQLite; README requires Windows 10 1903+ x64, WGC/H.264-capable GPU/driver, and disk space. Its supported overlay claim is specifically **borderless games**, not every fullscreen mode. These are project claims, corroborated in capture/player source, not independent runtime measurements. [README architecture and requirements](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/README.md#L194), [overlay scope](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/README.md#L48).
- **Actual capture:** `FramePumpService.cpp` creates a `GraphicsCaptureItem` with `CreateForWindow`, starts a WGC session with `StartCapture`, and maintains a window capture pipeline; this is substantive code, not merely an OBS wrapper claim. [CreateForWindow](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/src/capture/FramePumpService.cpp#L427), [StartCapture](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/src/capture/FramePumpService.cpp#L634).
- **Actual encoder/ring:** `SegmentRecorder::begin()` defaults to 30 fps, 12 Mbps, 5-second segments, 300-second retention when arguments are absent. It computes retained segment count by ceiling division. `createSegmentSink()` selects fragmented MP4, disables throttling, enables low latency and hardware transforms; `addVideoStream()` specifies H.264 output and RGB32 input. Enabling hardware transforms permits hardware encoding; it does not prove which encoder a specific machine chooses. Downscaling can run in D3D11, but comments and implementation explicitly include CPU readback/scaling fallback, so do not advertise zero-copy or negligible overhead. [begin](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/src/capture/SegmentRecorder.cpp#L66), [sink/encoder](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/src/capture/SegmentRecorder.cpp#L290).
- **Actual save concurrency:** `SegmentRecorder::snapshotForSave()` finalizes the in-flight segment, leases retained paths, opens the next recording segment and rebases its timestamps. `FramePumpWorker::runExport()` owns that lease on an export thread, remuxes compressed samples, and only publishes a finalized output. This deliberately keeps export off the capture worker, though closing/reopening the active segment still occurs at snapshot time. [snapshotForSave](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/src/capture/SegmentRecorder.cpp#L587), [runExport](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/src/capture/FramePumpService.cpp#L1008), [compressed sample remux](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/src/capture/ReplayExporter.cpp#L169).
- **Actual playback:** `OverlayViewer.qml` is a full-screen viewer inside the overlay, obtains video from `current.fileUrl`, and has seek and pause/play functions. `PlayerControls.qml` implements a seek bar and step controls. The inspected files do not expose speed or volume controls. A full-screen gallery viewer is a useful starting point but is not the requested compact picture-in-picture replay. [OverlayViewer](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/src/ui/qml/components/OverlayViewer.qml#L43), [file source](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/src/ui/qml/components/OverlayViewer.qml#L152), [PlayerControls](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/src/ui/qml/components/PlayerControls.qml#L244).
- **Actual focus behavior, with source conflict resolved:** `OverlayManager::show()` initially uses nonactivating presentation, then **immediately** calls `makeActivatable()` and bounded `ForegroundAcquirer::acquire()`. Thus current show and focus acquisition are coupled. `OverlayPresenter` maintains `WS_EX_NOACTIVATE` and `SWP_NOACTIVATE` during presentation/reassertion and has an explicit activatable transition. The comment atop `OverlayViewer.qml` saying the overlay never takes focus is stale against the manager code. Follow the executed manager logic, not that comment. Neither no-activate alone nor transparency of rendering proves mouse click-through. [show, lines 274–330](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/src/overlay/OverlayManager.cpp#L274), [presenter](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/src/overlay/OverlayPresenter.cpp#L40), [stale viewer comment](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/src/ui/qml/components/OverlayViewer.qml#L5).
- **License/maintenance, checked 2026-10-24:** current core LICENSE and README say GPL v3. Older search results/social copy describing MIT must not be used for the current tree. #### 2. WKImods/WKI-Clipper — best permissive recorder reference

- **Identity/platform:** Windows C#/.NET 8/WPF application with native capture helpers and external FFmpeg. Its README documents F9 as save last 15 seconds–30 minutes, Ctrl+F9 manual recording, and a separate widget board. It claims Windows 10 2004+/11 x64, RAM/disk buffering, window capture, game-only audio and editor. These are not claims that the saved clip immediately plays in a PiP. [README](https://github.com/WKImods/WKI-Clipper/blob/1b6aff3e9700b5868d252a3f1108b39c5ae773d9/README.md#L18), [architecture](https://github.com/WKImods/WKI-Clipper/blob/1b6aff3e9700b5868d252a3f1108b39c5ae773d9/README.md#L386).
- **Actual ring/save:** `ReplayBufferService` owns continuous FFmpeg recording, lifecycle serialization, per-generation capture/encoder identities and either a `MemorySegmentStore`/feed or disk ring. `SaveLastAsync()` snapshots one epoch, selects complete segments, materializes RAM footage to temporary files if necessary, invokes FFmpeg concat, waits for completion, finalizes `.part`, emits `ReplaySaved` and returns the output path. It refuses a concurrent save. This is save-then-play architecture, with deliberate protection against mixing windows/settings or overwriting material during a save. [state/epoch](https://github.com/WKImods/WKI-Clipper/blob/1b6aff3e9700b5868d252a3f1108b39c5ae773d9/WKI_Clipper/Services/ReplayBufferService.cs#L29), [SaveLastAsync](https://github.com/WKImods/WKI-Clipper/blob/1b6aff3e9700b5868d252a3f1108b39c5ae773d9/WKI_Clipper/Services/ReplayBufferService.cs#L1245), [concat/publication](https://github.com/WKImods/WKI-Clipper/blob/1b6aff3e9700b5868d252a3f1108b39c5ae773d9/WKI_Clipper/Services/ReplayBufferService.cs#L1350).
- **Actual capture/encode:** `FFmpegCommandBuilder.Build()` takes WGC BGRA named-pipe input when supplied; otherwise defaults to `ddagrab` display capture. AMD native `vsrc_amf` is opt-in and disabled when capture exclusion must be honored. Branches configure AMF/NVENC/QSV; normal `ddagrab` path includes hardware download, so hardware encode does not imply a zero-copy pipeline. `BuildConcat()` uses `-c copy`; segment output sets time/wrap controls; RAM mode uses MPEG-TS to stdout. `FFmpegService.HasEncoderAsync()` performs a real test encode rather than trusting `-encoders`. [command builder](https://github.com/WKImods/WKI-Clipper/blob/1b6aff3e9700b5868d252a3f1108b39c5ae773d9/WKI_Clipper/Services/FFmpegCommandBuilder.cs#L59), [concat/segments](https://github.com/WKImods/WKI-Clipper/blob/1b6aff3e9700b5868d252a3f1108b39c5ae773d9/WKI_Clipper/Services/FFmpegCommandBuilder.cs#L293), [encoder probe](https://github.com/WKImods/WKI-Clipper/blob/1b6aff3e9700b5868d252a3f1108b39c5ae773d9/WKI_Clipper/Services/FFmpegService.cs#L68).
- **Actual playback/UI:** `ClipEditorWindow` opens a saved path and uses WPF `MediaElement` with manual playback, volume initialized at 0.8, seeking and frame stepping. `OverlayWindow.ShowOnActiveMonitor()` directly calls `Show(); Activate(); Focus();`. This window is not a passive replay PiP. The broader README's click-through crosshair/performance widgets do not establish click-through clip playback. [ClipEditorWindow player](https://github.com/WKImods/WKI-Clipper/blob/1b6aff3e9700b5868d252a3f1108b39c5ae773d9/WKI_Clipper/Views/ClipEditorWindow.cs#L69), [file source](https://github.com/WKImods/WKI-Clipper/blob/1b6aff3e9700b5868d252a3f1108b39c5ae773d9/WKI_Clipper/Views/ClipEditorWindow.cs#L488), [overlay activation](https://github.com/WKImods/WKI-Clipper/blob/1b6aff3e9700b5868d252a3f1108b39c5ae773d9/WKI_Clipper/Views/OverlayWindow.xaml.cs#L39).
- **Limits distinguish claims from verification:** README says legacy exclusive fullscreen cannot be captured per window and falls back to monitor, segment boundaries can introduce approximately five seconds of replay-length deviation, AV1 RAM buffering is unsupported, and long saves can take 20–90 seconds. These are useful warnings, not independently benchmarked results. [limits](https://github.com/WKImods/WKI-Clipper/blob/1b6aff3e9700b5868d252a3f1108b39c5ae773d9/README.md#L431), [save time](https://github.com/WKImods/WKI-Clipper/blob/1b6aff3e9700b5868d252a3f1108b39c5ae773d9/README.md#L158).
- **License/maintenance:** root MIT License, copyright Phillip/WKI 2025–2026. Inspected master SHA `1b6aff3e9700b5868d252a3f1108b39c5ae773d9`, 2026-10-20T16:31:03Z, README screenshots commit. Repository created June 2026 and not archived; recent pushes alone do not establish production reliability. FFmpeg distribution and sound assets have their own licenses. [LICENSE](https://github.com/WKImods/WKI-Clipper/blob/1b6aff3e9700b5868d252a3f1108b39c5ae773d9/LICENSE), [commit](https://github.com/WKImods/WKI-Clipper/commit/1b6aff3e9700b5868d252a3f1108b39c5ae773d9), [metadata](https://api.github.com/repos/WKImods/WKI-Clipper).

#### 3. lulzsun/RePlays — libobs app reference

- **Architecture:** .NET 8 C# backend, TypeScript/React frontend in Windows WebView2; libobs recording. Linux is documented as work-in-progress. The project dates to 2021, making it older than the other two inspected projects. [README](https://github.com/lulzsun/RePlays/blob/db1abe5682ab37c731b1f2fd18412d40dd4eb2f6/README.md), [metadata](https://api.github.com/repos/lulzsun/RePlays).
- **Actual recording/ring:** `LibObsRecorder.SetupOutput()` creates OBS `replay_buffer` output with configurable duration and size, or `ffmpeg_muxer` for normal recording. Windows video source is OBS `game_capture`, with display-capture fallback. Encoders include NVENC, AMF, QSV and x264; audio uses WASAPI output/input/process capture and AAC. This is a practical reference for managing libobs, capture fallback and configurable recording. [capture identifiers](https://github.com/lulzsun/RePlays/blob/db1abe5682ab37c731b1f2fd18412d40dd4eb2f6/Classes/Recorders/LibObsRecorder.cs#L85), [output setup](https://github.com/lulzsun/RePlays/blob/db1abe5682ab37c731b1f2fd18412d40dd4eb2f6/Classes/Recorders/LibObsRecorder.cs#L337), [fallback](https://github.com/lulzsun/RePlays/blob/db1abe5682ab37c731b1f2fd18412d40dd4eb2f6/Classes/Recorders/LibObsRecorder.cs#L425), [encoder discovery](https://github.com/lulzsun/RePlays/blob/db1abe5682ab37c731b1f2fd18412d40dd4eb2f6/Classes/Recorders/LibObsRecorder.cs#L687).
- **Actual save/player:** `TrySaveReplayBufferAndBookmarks()` calls OBS output procedures `save` then `get_last_replay` and saves bookmarks for the resulting file path. `ClientApp/src/pages/Player.tsx` loads `${folder}/${game}/${video}` into HTML video, exposes playback rate, seeking/frame stepping and volume. This verifies a useful file-player UX, not an in-game PiP or a player reading OBS's active packet ring. [save](https://github.com/lulzsun/RePlays/blob/db1abe5682ab37c731b1f2fd18412d40dd4eb2f6/Classes/Recorders/LibObsRecorder.cs#L614), [player controls](https://github.com/lulzsun/RePlays/blob/db1abe5682ab37c731b1f2fd18412d40dd4eb2f6/ClientApp/src/pages/Player.tsx#L389), [video element](https://github.com/lulzsun/RePlays/blob/db1abe5682ab37c731b1f2fd18412d40dd4eb2f6/ClientApp/src/pages/Player.tsx#L480).

## What can be reused, and what must SmartReplay still build?

### Takeaway
Reuse the recorder, segment ownership, export isolation and Windows presentation patterns. Build the actual SmartReplay interaction as a separate state machine and playback path: visibility hotkey, explicit focus hotkey, passive click-through PiP, independent player clock, and a pinned snapshot that survives recorder rotation. Existing apps provide substantial foundations, not a ready-made implementation of the requested semantics. [GameHQ show](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/src/overlay/OverlayManager.cpp#L236), [snapshot](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/src/capture/SegmentRecorder.cpp#L587).

### Cited Findings
- **Priority 1 — GameHQ feasibility fork/spike:** retain WGC recorder, `SegmentLease`, snapshot retention and export threading; split `OverlayManager::show()` at the current present→makeActivatable boundary. Initial show should remain passive; focus hotkey invokes foreground acquisition; relinquishing focus restores game interaction without hiding playback. Implement actual hit-test/click-through policy rather than assuming `WS_EX_NOACTIVATE` does that. Current code already separates native presentation and foreground acquisition, making the change localized conceptually, but lifetime/controller policies will also need adjustment. [show boundary](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/src/overlay/OverlayManager.cpp#L274), [presenter](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/src/overlay/OverlayPresenter.cpp#L68), [input restoration](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/src/overlay/OverlayManager.cpp#L566).
- **Priority 2 — shorten trigger-to-first-frame path:** current GameHQ publishes finalized remuxed MP4 before normal file playback. For a dependable initial product, asynchronously snapshot/export a short interval and auto-open the resulting private temporary file; measure whether latency meets requirements. If not, design a player-facing segment playlist/custom demux or equivalent leased snapshot reader. That second path is new work; existing source does not prove it. Retain recorder independence and delay deletion until player release. [export/publication](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/src/capture/FramePumpService.cpp#L1029), [file-only player](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/src/ui/qml/components/OverlayViewer.qml#L157).
- **Priority 3 — UI/player:** replace full overlay gallery flow with a small resizable/movable replay surface; add rate, seek, volume/mute and an obvious passive/interactive indication. RePlays' `handlePlaybackRate`, volume slider and time navigation are concrete UX references, while GameHQ already supplies seek/pause and a Qt media stage. Neither is evidence that all controls work under the desired two-hotkey semantics. [RePlays controls](https://github.com/lulzsun/RePlays/blob/db1abe5682ab37c731b1f2fd18412d40dd4eb2f6/ClientApp/src/pages/Player.tsx#L389), [GameHQ seek/play](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/src/ui/qml/components/OverlayViewer.qml#L69).
- **Priority 4 — permissive alternative:** use WKI's epoch/identity guards, ring planning, save pinning and encoder-probe ideas if avoiding a GPL app fork. Its FFmpeg capture path includes GPU↔CPU copies; treat it as correctness/reference code, then profile before choosing it for the low-overhead requirement. [epoch/ring state](https://github.com/WKImods/WKI-Clipper/blob/1b6aff3e9700b5868d252a3f1108b39c5ae773d9/WKI_Clipper/Services/ReplayBufferService.cs#L75), [capture filters](https://github.com/WKImods/WKI-Clipper/blob/1b6aff3e9700b5868d252a3f1108b39c5ae773d9/WKI_Clipper/Services/FFmpegCommandBuilder.cs#L185).

### Inferences
- A source-inspected candidate should be built/tested before committing to the complete fork: recorder latency and overlay focus behavior are the decision gates. Existing broad libraries/widgets are valuable but also increase code surface beyond SmartReplay's core. [GameHQ capture/export](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/src/capture/FramePumpService.cpp), [WKI architecture](https://github.com/WKImods/WKI-Clipper/blob/1b6aff3e9700b5868d252a3f1108b39c5ae773d9/README.md#L386).

### Gaps
- Required tests remain: borderless and exclusive fullscreen separately; DirectX/Vulkan/OpenGL; NVIDIA/AMD/Intel; hotkey conflicts; anti-cheat titles; HDR/mixed DPI/multiple monitors; capture exclusion of replay itself; audio feedback/echo; controller/game input after focus transitions; hotkey-to-first-frame and steady-state CPU/GPU/frame-time overhead; save/seek during ring rotation; target-window resize/device reset/crash recovery.
- The user's Python HUD-discovery spike provides none of this UI/recorder implementation by the supplied context; this research did not inspect local production files and makes no further implementation claim.

## Is manual in-game PiP replay frontier territory?

### Takeaway
The basic concept has direct commercial prior art, not merely adjacent screen-recording tools: AMD officially documented hotkey-triggered In-Game Replay over the game screen years ago. The differentiator can be a reliable GPU-independent Windows implementation with better playback controls and explicit passive/focused behavior; that is a product/engineering opportunity, not evidence of a novel recording or replay invention. [AMD In-Game Replay](https://www.amd.com/en/resources/support-articles/faqs/DH-023.html).

### Cited Findings
- AMD's official ReLive support page describes an immediate short replay over the running game, opened by assigned hotkey, with duration 5–30 seconds and configurable overlay size/position. It requires Instant Replay enabled and identifies the feature as introduced in Adrenalin 2019 Edition (18.12.2). This is close prior art to the user's core manual PiP behavior. The page does not establish the user's separate focus toggle, seeking/speed controls, cross-vendor support or current 2026 driver behavior. [AMD support](https://www.amd.com/en/resources/support-articles/faqs/DH-023.html).
- NVIDIA's official NVIDIA App overview documents Instant Replay as saving a recent clip on hotkey and an overlay Gallery after first capture; this supports broad existing capture/review overlap but is weaker evidence of direct PiP replay than AMD's explicit feature. [NVIDIA App features](https://www.nvidia.com/en-ph/geforce/news/nvidia-app-download-and-features/).
- Medal's official guide documents automatic game detection, in-game overlay capture options and F8 saving recent gameplay, up to 20 minutes. It does not establish direct independent PiP review under the requested focus semantics. [Medal recording guide](https://support.medal.tv/support/solutions/articles/48001157618-how-to-make-clips).
- The inspected GameHQ implementation supplies an open-source in-game saved-file player and continuous recorder already; therefore “open source cross-game recording plus an in-game video gallery” is also existing work. [GameHQ viewer](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/src/ui/qml/components/OverlayViewer.qml), [recorder](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/src/capture/SegmentRecorder.cpp).

### Inferences
- Avoid pitching SmartReplay as the first hotkey-triggered replay overlay. A defensible narrower pitch would emphasize measurable responsiveness, precise playback control, passive/focus separation and dependable support across GPU vendors/games, after validating those properties. [AMD prior art](https://www.amd.com/en/resources/support-articles/faqs/DH-023.html), [GameHQ focus coupling](https://github.com/UnderFusion/GameHQ/blob/f8a8ebc6593bc04bdba6a5d8dfca81cfe9e07637/src/overlay/OverlayManager.cpp#L318).

### Gaps
- This is a targeted source review, not an exhaustive market, repository or patent search. It cannot prove absence of an open-source exact match. AMD current compatibility and real playback behavior were not tested. No patentability/legal-novelty conclusion is made.
